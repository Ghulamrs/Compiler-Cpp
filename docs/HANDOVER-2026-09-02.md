## The Windows box runs again

It was **Smart App Control**, not a deployed WDAC policy, and the evidence was
the pattern rather than the message: 36 of 225 executables blocked and the rest
allowed. A policy is a rule and would have taken all 225 — every case is an
unsigned binary built the same way in the same directory. Selective blocking is
reputation, which is what SAC does. `VerifiedAndReputablePolicyState` under
`HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy` read `1`; it now reads `0`.

Turning it off is **irreversible** - Microsoft gives no way back short of
reinstalling Windows. That was the user's call and it was taken knowingly.

Measured on `main` after it was turned off:

    windows cases:       225 passed, 0 failed
    windows names vs cl:  96 agreed, 0 differed, 24 skipped
    throw-check / sret-check / catch-check: all pass

**So the blocker the 09-01 handover called the one that mattered most is gone**,
and with it the caveat that `e9cf149` and `912a4bf` open with. A-01 is settled
by cl itself rather than by clang standing in for it. A note for whoever writes
the next status table: a suite whose pass count depends on a cloud reputation
service is not a stable oracle, which is the real argument for having turned it
off on a dedicated test box.

## The three branches

Fable 5.1, one agent per area, each in its own worktree, each told that **a
finding counts as mended only if a neighbouring shape it did not use the first
time also passes**. That instruction earned its keep for the second round
running: all three agents found something past the fault they were sent for.

| `fable/sem-mend` | `8c2e9f3` | 235 / 366 / 123 / 26 |

All three build clean and are Mac-only: none has seen `tools/verify-three`, by
instruction, because three concurrent builds would thrash a 419 MiB instance.

**The six that were open are all addressed.** Base default-argument segfault,
negative class-layout size and the floating lanes on `src-mend`; `new P()`
value-initialisation on `sem-mend`; `goto` past an initialisation and narrowing
in list-initialisation on `lang-mend`.

**The 09-01 warning about the rescued WIP was right.** `be7ab3e` was missing its
base-default-argument fix entirely - the file its author said a `git checkout`
had wiped - and the audit's three lines still exited 139. Its other two thirds
were present and sound. `5507323` on `sem-mend`, by contrast, built and passed
exactly as committed.

**Three faults found beside the work:**

- `clonePure` dropped a global's linker symbol, so `++n` emitted `EXTERN n:PROC`
  against a definition of `?n@@3HA` - a link error on the Windows target only.
  Fixed, `62f268c`.
- The refusal `CLAUDE.md` describes for `goto` out of a scope holding a live
  object was **unreachable**: `consume("goto")` returned before the `alive_`
  check. `{ S s; if (n) goto out; } out:` never ran `~S`. A documented safety
  net that had never once fired. Now refused by name, and the honest fix - a
  jump that destroys what it leaves - needs jumps to know their scopes.
- **Open, silent:** a user-written constructor never builds a class-typed member
  it does not name. `struct S { M m; S() {} };` prints 1 where clang prints 3.
  The loud form `: m(1)` is refused, so only the silent shape is live.

   three fast-forwards, and a rebuild between each.
2. **Three-box verify whatever merges.** Worth more than it was this morning:
   the Windows leg now measures 225 rather than 189 and a set of assumptions.
3. **Settle a baseline that does not reconcile.** The lang agent reports its
   pre-change baseline as 226 / 348 / 107 / 26. `main` measured 228 / 357 / 120
   / 26 here from a clean build, and that branch is cut from that same commit.
   One of the two numbers is against something other than what it names. The
   house rule says a green suite proves nothing until you prove what it ran
   against, so settle this before quoting either.

   expected-refusal form. The floating-lane work wanted one.
5. **`CLAUDE.md`'s status table is behind** - it still says 223 / 348 / 117 / 26
   and Windows 220 / 93.
