## The three-box gap the previous round left, and the structural thing under it

`template-nontype-numeric` arrived with `445f84a` carrying neither `.nonames`
nor `.nocl`, where every other case including a C++ standard library header
carries both. clang compiles such a case against *clang's* library and cxx1
against `include/`, so the two symbol lists are two implementations - 299 lines
apart. The markers were the fix; **why nobody saw it is the part to keep.**

**`names.sh` asks clang for all three ABIs, and only the native one has a C++
library to compile against.** The other two answer "clang refused it, so there
is nothing to compare", and the case passes vacuously. So for a case that
includes a library header the comparison runs on **exactly one machine per
box**, and for this one that machine is the Mac. The 09-08 round was done
entirely from Windows, where `names.sh` read 249/1 with this case never compared
at all. Nothing about the compiler was wrong: `run.sh` and `emit.sh` put it
through all three targets and were green throughout.

**The Linux leg answered the other question only it can.** `src/` still builds
clean under real g++ 11.5.0 with `-std=c++14 -Wall -Wextra -Werror -pedantic`.
Apple's libc++ hands you C++17 names in C++14 mode, so a clean Mac build is not
evidence of that - and the 09-08 handover's Linux evidence was assembly shipped
from Windows, which it says plainly does not answer it either.

## The audit, and the one thing missing from it

**A conformance audit found four places where cxx1 gave a wrong answer with no
diagnostic**, and a fifth was recorded beside them. All five are closed now.
`8e33f5c` took four and `7e8819b` the fifth.

**Unlike 2026-09-01 and 2026-09-06, this audit has no frozen report.** There is
no `docs/audit-2026-09-08.html`, so the commit messages are the whole record of
what was probed and what was ruled out. That is a departure from the rule those
two files exist to keep - a later reader can tell what was true on the day only
if the day wrote something down - and it is worth either writing the report from
the probes or saying deliberately that this one was small enough not to need it.

## The fifth: a virtual base's mem-initialiser was dropped

**The symptom read as a bad offset and was a subobject never written.** Reading
a data member of a virtual base gave garbage; the vptr and the `vbase_offset`
were both correct. [class.base.init]/7 gives every virtual base to the
most-derived constructor, and that split was right - C2 skips them, C1 builds
them - but **C1 only ever asked for a *default* constructor**, so the
mem-initialiser list was parsed, checked for errors and then dropped. `L() : B(7)`
ran `B()` and lost the 7; where B had no default constructor it built nothing
and left the subobject holding the stack. Silent both ways, and 09-08's
CONFORMANCE entry had it exactly the wrong way round.

**`virtual-base-diamond` did not catch it because its classes carry no data.**
It counts constructor calls, and a call *was* made - the wrong one. A case that
counts calls cannot see which constructor answered.

**What made the fix small is that C1's frame now matches C2's slot for slot.**
The arguments are parsed in C2's scope and emitted in C1's body, where they name
`Var::local(name, slot)`, so the slot has to mean the same thing in both.
`topLevel` declares a constructor's parameters first and `this` last, then
inserts `this` at the front of the `Param` list - frame order and calling
convention are already independent there - while `synthesizeCompleteCtor`
allocated `this` first and put every argument one slot out. Allocating in C2's
order lets the expressions be reused verbatim, with no second parse.

## The other half of [except.spec]/9, built out of the finished body

**An exception arriving from a callee cannot be seen from the throw site**, so
this one needs a landing pad over the whole body - and `docs/CONFORMANCE.md` had
said it would have to be paid for with refusals. It was not, because of where
the region is built.

**An implicit `try` written around the *parse* sets `inTryBody_` before the body
is read**, and `for (S s; ...)` is refused under that flag on every target - so
wrapping the parse would have started refusing `noexcept` functions that compile
today. Building the region out of the finished body sets no flag while anything
is being read. Nothing that compiled before is refused now, and gating on
`mayThrow_` as well means a `noexcept` function calling only what has promised
gets no region at all, which is why 991 assembly goldens did not move.

**The one real limit was found by the region failing rather than reasoned
about.** A body that already owns an unwind region cannot be wrapped after the
fact: its cleanup row resumes, the resume finds this frame again, and the
destructor runs for ever -

```
before +9 -9 -9 -9 -9 -9 -9 -9 ...
```

Handing over instead of resuming is what `tryChainLabel_` and `tryBodySegments_`
are for, and a segment learns its chain when it is *built* - so covering those
bodies means setting the chain up before the body is parsed, which is the cost
this declined to pay. `functionHasPads_` is the test.

## Two pieces of plumbing, and where each came from

**`gnuSyntax_` was a file-scope `bool` in `X86_64Windows.cpp`**, written from
argv and read by the backend and the Driver: one mutable object shared by every
compiling thread, correct only while nothing wrote it after the pool started -
a constraint its own comment stated and nothing enforced. It is an option of the
invocation, so it lives beside `threads_` on the Driver and is handed over at
the call. The three backends stay const singletons. **Found by pointing
`no-shared-state` at the whole of `obj/`**, which it had never been asked to
read - it was written against the parser directory. Of the four candidates it
reports, three are the `static const` Backend singletons landing in writable
data because a vtable's vptr is written at construction, and are not races.

**`verify-three` excluded iCloud's `name 2.ext` copies going out and not coming
back.** The two comparison loops globbed `tests/cases/*.expected` and `*.error`
unfiltered on this side, so each duplicate was looked for in a log it was never
in: the Windows leg reported 125 additional failures, every one of the form
`access-through-base 2: did not run`, on a run whose 413 real cases matched the
baseline exactly. Same filter as the send side, applied to both loops.

## What is open

1. **The Microsoft virtual-base layout.** A virtual base is a vbtable on that
   ABI, none of it has been measured against cl, and cl says `sizeof` is 24
   where cxx1 says 16. **The message that refuses it is now inaccurate**:
   `hasVptr()` is `polymorphic() || hasVirtualBase()`, so a class with no
   virtual function at all is turned away with *"'Dia' has virtual functions in
   a base that is not the first"*. Both `virtual-base-diamond.notarget` and
   `virtual-base-initialiser.notarget` record it; the wording is the cheap half
   and the layout is the real one.
2. **`noexcept` where the function owns an unwind region** - a destructible
   local or a `try` - and the whole of it on x86_64-windows, where a handler is
   a funclet and a state in the FH3 tables rather than a row in a call-site
   list. `msTryStatement` is untouched.
3. **A mem-initialiser argument that needs a temporary of its own**, `: V(f())`
   for a class-returning `f`. It is allocated in C2's frame, which C1 cannot
   read; refused by name rather than emitted wrong. `: V(v + 10)` over the
   parameters works.
4. **Make `-masm=gnu` the Windows default, or decide not to.** `585baf2` moved
   the choice out of a file-scope global and into the Driver, which is the
   plumbing and **not** the decision: flipping the default still moves every
   Windows golden file and re-bases `names-vs-cl`, both of which run the default
   syntax.
5. **The temp-batch race in `Driver::runTool`**, still at `src/Driver.cpp:225-236`:
   `GetTempFileNameA` then `std::remove` then a rename to `.cmd` discards the
   uniqueness, so a one-shot `cxx1 a.cpp b.cpp -o out.exe` can fail on the box
   before it reaches the linker. Compiling with `-c` and linking separately
   avoids it.
6. **`tests/run.sh` still does not say it is meaningless on the Windows box.**
   Its header says it is the host-target suite; what it does not say is that it
   byte-compares against LF `.expected` files while the CRT writes CRLF, so it
   reported 179 passed / 248 failed on a tree whose Windows leg was clean.
   `run-cases.cmd` is the suite there.
7. **The four gaps met writing `<type_traits>`**, unchanged: `template <class T, T v>`;
   a typedef naming a template-id used as a **base**, resolved at instantiation;
   a partial specialization on an array of unknown bound, `X<T []>`; and an
   out-of-line constructor of a class template.
8. **The audit has no frozen report**, unlike its two predecessors.
