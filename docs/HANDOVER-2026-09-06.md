## The method that found all of it

**Classify by *how* the compiler refuses, not by whether the program
compiles.** One minimal program per feature, each first validated as conforming
by `clang++ -std=c++11 -pedantic-errors`, then sorted into three buckets:
compiles / refused **by name** / refused by a message naming no feature. The
third bucket is invisible: `tools/exclusions` derives its list from refusals
that say "not supported yet" or name a standard, so a generic `expected ';'`
can never be listed and never gets fixed.

105 probes over two grids found **24** such gaps. All are now named; both grids
read 63 compiling, 41 refused by name, **0 invisible**.

**The grid is not the standard.** The second grid found seven the first missed
purely by asking different questions — including two **C++98** features
(anonymous union, function try block). A third would find more. The user's
own C++ keyword list already surfaced one this way: see below.

## The one fact most likely to be re-broken

**The Itanium call-site rows are written innermost-first, not sorted by
address, and that is deliberate.** The personality routine scans linearly and
takes the *first* row whose range contains the address, so a region nested
inside another must be listed before it.

Sorting them by address looks obviously right, fixes a real problem (a region
inside a landing pad closes after the row that begins earlier), changes 14
emitted files, and **silently breaks unwinding through a nested scope**:

```cpp
A outer("outer");
{ A inner("inner"); boom(); }     // clang: ~inner ~outer     sorted: ~outer
```

All four suites stay green through that. What caught it was the **emit
golden**: it had read `0 of 675` all session, and the moment it did not, one
diff plus a purpose-written program found the leak, and `git stash` + rebuild
proved the regression was mine. The sort is reverted with a comment where it
was.

## Standing habits confirmed again this round

  version.** `throw;` outside a handler is well-formed and terminating
