### The virtual-base split, which the 09-07 handover set as the next thing

That handover named it exactly: C1 and C2 are two names on one body, and with a
virtual base they cannot be. What it did not know is that the **implicit** path
was worse than wrong - it reached its virtual base *through the vtable*, whose
vptr is not stored until the bases are built, so

```cpp
struct V { V(); ~V(); };  struct D : virtual public V { };   D x;   // segfault
```

segfaulted on Itanium with no constructor written anywhere. Three paths needed
the split - the written constructor in `ParserTopLevel`, `synthesizeDefaultCtor`
and `synthesizeCopy` - and the copy takes it with the source forwarded, so
`Dia b(a)` copy-constructs the one `V` out of `a`'s.

Verified by **running on the Linux box**: five shapes, all matching clang,
including the three that segfaulted. The emit golden read 2 of 735 changed,
both of them the new case.

**Still refused, and neither is needed yet:** the VTT and the construction
vtables, which nothing wants until a virtual function is called from inside a
base constructor; and the whole feature on x86_64-windows, where a virtual base
is a vbtable and **cl says `sizeof` is 24 where cxx1 says 16** - measured on
this box, and recorded in `tests/cases/virtual-base-diamond.notarget`.

### Compiler++ links on Windows, and what it cost to find out

`ml64` has no COMDAT directive, so every mergeable definition is exported by
each translation unit that needs it. Building Compiler++'s sixteen sources gave
**3592 LNK2005 over 518 distinct symbols** - 48 vtables and 470 inline, template
and implicit members.

**Two answers were measured and rejected**, and the measurements are the useful
part:

- **File-local**, which is the precedent rung 6.5a set for the throw RTTI.
  Links and runs - but vtables alone leave the 470 functions standing, and
  withdrawing everything costs `names-vs-cl` 17 cases where cl exports a vtable
  External, on top of the 51 already recorded.
- **A key function.** Dead by census: of the 48 colliding classes **43 have
  none**, every virtual being inline or pure. And cl does not use one anyway -
  measured here, it emits the vftable External in *both* objects.

What was already true and unreachable is that the **GNU spelling links with no
duplicates at all**, clang writing the same COFF and being able to mark a
section COMDAT. The driver simply never called it: `Driver::link` and
`Driver::assembleObjects` both built an `ml64` command whatever `-masm=` said.

### The three EH gaps under it

Each was hidden by the one before it, and only the third mattered:

1. `X86_64Linux::endFunclet` wrote the raw `.L` resume label where every table
   entry around it already goes through `labelText`. One call.
2. The Microsoft throw-info chain had no GNU twin, so anything that threw
   assembled and failed at link on `_TI`.
3. **There was no try map.** `emitCoffCleanupTables` was the only FH3 emitter
   here, so a frame that *catches* was described as one that only cleans up -
   `nTryBlocks` 0, no handler map - and a `try`/`catch` linked, ran, **caught
   nothing and printed nothing**. It also wrote `.long @IMGREL` with no symbol
   for a state with no funclet, which the assembler took as a reference to a
   symbol named `?`.

`emitCoffTryTables` is the GNU twin of the MASM try emitter, and the dispatch
asks `msTries()[0].isCleanup` in the same words `MasmCodeGen` does.

## What is open

1. **arm64-darwin, for all five commits.** Nothing here has seen a Mac.
2. **Make `-masm=gnu` the Windows default, or decide not to.** It is level with
   MASM now on every measure taken here. What it would cost is one re-record of
   the emit golden and one re-measure of `names-vs-cl`, and what it would buy is
   that a multi-file C++ program links on Windows without a flag.
3. **`tests/run.sh` cannot be used on the Windows box, and the number it gives
   is meaningless there.** It byte-compares program output against `.expected`,
   and the CRT turns `\n` into CRLF while `.expected` is LF - so it reported
   179 passed, 248 failed on a tree whose Windows leg was 235 / 0.
   `run-cases.cmd` is the suite for this box; `run.sh`'s own header does not
   say so.
4. **A temp-batch race in `Driver::runTool`** (`Driver.cpp:224-236`):
   `GetTempFileNameA` then `remove` then a rename to `.cmd` discards the
   uniqueness, so a one-shot `cxx1 a.cpp b.cpp -o out.exe` can fail on this box
   before it reaches the linker. Compiling with `-c` and linking separately
   avoids it. Found by Fable 5.1 while measuring the COMDAT options.
5. **Four gaps of one family, each an anonymous refusal or a missing shape**,
   all met while writing `<type_traits>` and the new case:
   - `template <class T, T v>` - a non-type parameter whose type is the
     parameter before it. This is why `integral_constant` is not in the header.
   - a typedef naming a template-id used as a **base**, resolved at
     instantiation. This is why the traits derive from `_bool_constant<false>`
     rather than from `false_type`.
   - a partial specialization on an **array of unknown bound**, `X<T []>`,
     which stops with `target: no size for this type yet`. A pattern is a shape
     and needs no size. Same message a template parameter used as an array
     element gives, which the 09-06 handover already recorded.
   - an out-of-line **constructor of a class template**, refused by name.
6. **The Microsoft virtual-base layout**, which cl says is 24 bytes where cxx1
   says 16, and where reading a member stops with `codegen: this has no
   address` - a message naming no feature, which is the invisible bucket the
   09-06 sweep exists to empty.

## Two habits this round would have been shorter for

**Run the same command twice before believing a number.** Two Windows sweeps
reported `0 passed, 235 failed` and neither was a compiler result: one invoked
`cxx1-msvc.exe` bare inside a batch, where cmd does not search the current
directory, and the other was a `sed` that ate `\c` and produced
`.x1-msvc.exe`. Reading the `.build` log rather than the score is what caught
both. The 09-06 handover says the same thing about a bisect over an
intermittent fault.

**A truncated error list is not the error list.** The COMDAT investigation
began from `head`-ing a link failure and reporting the first 25 lines - all
vtables - as though they were all of it. The real figure was 518 symbols, 470
of them functions, and it changed which fix was right.
